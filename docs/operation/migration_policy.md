# FontaineRepublic Server Migration Policy v1.0

## 一、背景

当前存在一个旧 Forge Minecraft 服务器，玩家正在其中游玩。未来 FontaineRepublic 正式服务器将作为新服务器独立启动。

**旧服务器不会直接升级为新服务器。** 新服务器将重新生成世界、重新进行土地规划，玩家从共和国成立开始发展。

旧服务器与新服务器之间的关系是：

> 旧时代资产清算 → 新共和国启动

而非：

> 旧存档升级 → 继续经营

---

## 二、核心迁移原则

### 原则1：新时代，新世界

新服务器生成全新世界。旧世界的建筑、地形、物品不直接导入。

### 原则2：资产清算，而非资产复制

旧玩家的资产不是1:1复制到新服务器。旧资产经过评估和折算后，转换为新共和国的启动资金。

### 原则3：折算，而非等价

旧资产不按市场价格1:1兑换。通过折算比例控制旧资产对新经济的影响。

### 原则4：公平优先

旧玩家的资产优势不应破坏新服务器的经济平衡和新玩家的公平参与。

### 原则5：人工评估，非自动迁移

旧世界资产由管理员人工评估，不通过 Mod 自动扫描或自动转换。

### 原则6：运营流程，非 Mod 功能

迁移系统不进入 FontaineRepublic Alpha 阶段开发。它是服务器运营流程，由管理员手动执行。

---

## 三、迁移流程

整个迁移分为三个阶段。

### 阶段1：旧服务器资产冻结

**时间**：新服务器启动前1-2周。

**操作**：

1. 发布服务器公告，通知玩家即将进入新时代
2. 停止旧服务器的核心经济系统运行
3. 冻结所有玩家交易和资产变动
4. 管理员开始记录玩家资产

**记录内容**：

| 项目 | 说明 | 记录方式 |
|------|------|----------|
| 玩家 UUID | 唯一标识 | 从旧服务端配置文件导出 |
| 玩家名称 | 当前用户名 | 导出 |
| 可兑换资源 | 矿物、建材、农产品等 | `数量 × 物品类型` |
| 建筑资产 | 玩家建造的建筑物 | 坐标 + 截图 |
| 特殊资产 | 稀有装备、收藏品、成就物品 | 物品名 + NBT 数据 |

**输出**：每个玩家一份资产清单（JSON 文件），存储在 `migration/` 目录下。

### 阶段2：资产评估

将旧资产分类为三类，分别评估。

#### A 类：可交易资源

**包含**：
- 矿物（铁、金、钻石、下界合金等）
- 建材（石头、木材、玻璃等）
- 农产品（作物、食物等）
- 可出售物资（怪物掉落物等）

**计算公式**：

```
A类资产价值 = Σ (每种物品数量 × FontaineRepublic官方基础价格) × 折算比例
```

**官方基础价格**：使用 FontaineRepublic Economy 模块中定义的基础价格表。旧服务器物品价格不参与计算。

**折算比例**：默认 50%。可配置，由管理员在新服务器启动前确定并公布。

#### B 类：建筑资产

**不按方块数量计算。** 采用人工评估。

**评估等级**：

| 等级 | 描述 | 对应价值（共和国货币） |
|------|------|------------------------|
| 无价值 | 小型临时建筑、简陋小屋 | 0 |
| 普通 | 功能性住宅、中型建筑 | 10,000 - 50,000 |
| 优秀 | 大型复杂建筑、城镇核心建筑 | 50,000 - 200,000 |
| 历史/特殊 | 服务器标志性建筑、公认地标 | 200,000 - 500,000 |

**评估方式**：
- 管理员截图旧建筑，在新服务器启动前公布截图供玩家确认
- 由 2 名以上 COUNCIL 成员共同评估等级
- 最终结果公示 3 天，接受异议

**不评估的建筑**：
- 已被破坏或未完成的建筑
- 违规建筑（需旧服务器管理员确认）
- 玩家声明放弃评估的建筑

#### C 类：特殊物品

**包含**：
- 稀有附魔装备
- 收藏品（龙头、唱片、旗帜等）
- 特殊成就物品（自定义命名物品等）
- 服务器活动限定物品

**评估方式**：逐件评估。由管理员和物品持有者协商确定价值。

**单件价值上限**：不超过 50,000 共和国货币（防止单件物品过度影响新经济）。

### 阶段3：资产转换

旧资产转换为新共和国的启动资金。

**转换规则**：

```
最终启动资金 = A类资产价值 + B类建筑评估价值 + C类特殊物品价值
```

**转换方式**：
- 玩家在新服务器注册后，管理员通过 `/fr economy give <player> <amount>` 命令发放
- 不直接给物品。旧物品不进入新服务器
- 发放时间：新服务器启动后 3 天内完成

**示例**：

```
玩家 Alice：
  A类：铁锭 64个 × 100 × 50% = 3,200
       钻石 10个 × 1,000 × 50% = 5,000
  B类：主城广场参与建设 → 优秀 → 100,000
  C类：无
  合计：108,200 共和国货币

玩家 Bob：
  A类：圆石 640个 × 10 × 50% = 3,200
  B类：小型木屋 → 普通 → 20,000
  C类：附魔钻石剑 → 30,000
  合计：53,200 共和国货币
```

## 四、设计原因

### 为什么不全额继承旧资产？

1. **防止经济失衡**：如果所有旧资产1:1复制，老玩家在新服务器第一天就拥有巨大财富，新玩家永远追不上
2. **保护新土地制度**：FontaineRepublic 的土地所有权属于共和国。旧建筑如果直接导入，会破坏 UsageRight 制度
3. **符合世界观**：共和国成立是一个新时代的开始。旧时代的财富通过"清算"转化为新时代的启动资金，符合叙事
4. **公平参与**：所有玩家从接近的起跑线开始，共同建设共和国

### 为什么不由 Mod 自动执行？

1. **数据异构**：旧服务器可能使用了不同的 Mod 组合、不同的数据格式，自动迁移容易出错
2. **运维灵活性**：人工评估允许管理员根据实际情况灵活调整，而不是被脚本束缚
3. **减少 Alpha 复杂度**：迁移是一次性事件，不值得投入 Alpha 开发资源

## 五、与 FontaineRepublic Mod 的关系

**迁移系统不进入 Alpha 阶段开发。**

| 关联内容 | 关系 |
|----------|------|
| Core / Citizen / Land / Economy | 无关。迁移是运营流程 |
| `/fr economy give` | 可用于手动发放启动资金（Alpha 0.2） |
| Economy 模块的基础价格表 | 用作 A 类资产评估的参考价格 |
| Citizen 模块 | 旧玩家 UUID 可在新服务器直接注册 |

**发放启动资金的方式**（在 Alpha 0.2+ 可用）：

```
/fr economy give <player> <amount>
```

在 Economy 模块实现之前，管理员可直接编辑 SavedData 或使用临时脚本。

## 六、Future Extension（远期）

以下功能在本次文档中明确不设计、不实现。仅作为远期参考方向。

| 方向 | 说明 | 最低条件 |
|------|------|----------|
| 自动化资产扫描 | Mod 读取旧世界存档，自动统计物品 | Economy + Resource 模块成熟后 |
| 建筑自动截图 | 根据坐标自动截取建筑图片供评估 | Beta 阶段 |
| 迁移 GUI | 图形化迁移管理工具 | Beta 阶段 |
| 资产继承申请 | 玩家在游戏内提交资产清单 | 不早于 Alpha 0.3 |
| 多次迁移支持 | 支持分批次、分阶段迁移 | 不早于 Beta |

---

## 七、执行检查清单

旧服务器关闭前：

- [ ] 发布新时代公告（至少提前 2 周）
- [ ] 冻结经济系统
- [ ] 导出所有玩家 UUID 和名称
- [ ] 截图所有需要评估的建筑
- [ ] 记录每位玩家的 A 类资源清单
- [ ] 记录每位玩家的 C 类特殊物品清单

新服务器启动前：

- [ ] 确定折算比例并公告
- [ ] 完成 B 类建筑人工评估
- [ ] 完成 C 类物品人工评估
- [ ] 计算每位玩家的最终启动资金
- [ ] 公示所有玩家资产清算结果（3 天公示期）

新服务器启动后：

- [ ] 玩家注册 Citizen
- [ ] 管理员发放启动资金（3 天内完成）
- [ ] 归档所有迁移记录
- [ ] 旧服务器降级为只读/关闭
